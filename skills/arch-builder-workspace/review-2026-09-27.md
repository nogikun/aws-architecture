## 主な所見

### 1. 図の批評は有効だが、最後の合格条件が甘い

- [Iteration 1 Fargate の最終批評](iteration-1/eval-1-fargate-aurora-web/with_skill/run-1/outputs/.arch-loop/fargate-aurora-web/round-2/critique.json) は `pass: false`、legibility 3。修正後の再批評も行われていないことを[報告書](iteration-1/eval-1-fargate-aurora-web/with_skill/run-1/outputs/report.md)自身が記録している。benchmark 側ではこの図も全アサーション合格として数えている。
- Iteration 2 Fargate は pass だが、ECS-c から Aurora Writer への線が Reader の近くを通り、誤読されるという `should` が残る。[最終批評](iteration-2/eval-1-fargate-aurora-web/with_skill/run-1/outputs/.arch-loop/fargate-aurora-web/round-2/critique.json)
- サーバーレス図は pass だが、Worker Lambda → DynamoDB の矢印が左向きに戻る点を `should` として残している。[最終図](iteration-2/eval-2-serverless-orders/with_skill/run-1/outputs/serverless-orders.png)、[批評](iteration-2/eval-2-serverless-orders/with_skill/run-1/outputs/.arch-loop/serverless-orders/round-1/critique.json)
- 図の批評基準は「全軸4以上、must指摘なし」で pass になるため、読み違いにつながる `should` が残っても合格できる。[diagram-critic.md](../arch-builder/agents/diagram-critic.md)

**改善案:** 最後に修正した画像を必ずもう一度批評へ通す。ユーザーが「厳しめ」と求める場合は、矢印の誤読や主要経路の曖昧さに関する `should` も解消するか、未解決として明示する。

### 2. ベンチマークの反復数が合わない

[benchmark.json](iteration-1/benchmark.json) は `runs_per_configuration: 3` と記載する一方、保存された実行行は6件で、各評価ケース・各条件に `run_number: 1` が1つずつあるだけ。`±` の値は同じケースを繰り返したばらつきではなく、異なる3ケース間の差である。したがって「with-skill 100%」は今回の3ケースのアサーション通過率であり、再現性のある成功率とはいえない。

アサーションもファイルの存在、lint、特定サービスの配置が中心で、線の交差・ラベルの可読性・読者が経路を誤解しないかを直接採点していない。Iteration 2 には with-skill の `grading.json` と benchmark 集計がなく、評価途中の状態。

**改善案:** 1プロンプト・1条件あたり3回を実行して run 1〜3 を保存し、実行モデルと評価モデルを記録する。機械判定、設計レビュー、PNGのみを使う図の読みやすさ採点を分離する。

### 3. 現行のAWS情報を設計に取り込む手順がない

スキルは公式アイコン、ローカル lint 規則、固定された参照資料を使う。現在のサービス仕様、東京リージョンでの利用可否、最近の変更を確認する段取りは明示されていない。AWS icon package 自体も四半期ごとに更新されるため、アイコンライブラリの更新時点を残すとよい。

**改善案:** YAMLを作る前に、不確かなサービス仕様・新機能・リージョン対応だけを公式資料で検索・再取得し、設計報告に確認日と出典URLを短く残す。質問文に社内限定・インターネット公開などが明記されない場合は、アクセス経路を勝手に確定せず図中の前提として宣言する。

## AWSの最新ナレッジ取得方法

| 手段 | 利用可否・制限 |
|---|---|
| ブラウザ検索 | AWS公式ドキュメントは公開されている。今回も公式ページをWeb検索で参照した。 |
| AWS Knowledge MCP | AWS Labsの現行ページはGAとして案内。Streamable HTTPの接続先は `https://knowledge-mcp.global.api.aws`。検索、ページ取得、リージョン一覧・利用可否、AWSスキル取得に使える。AWSアカウントや認証情報は不要だが、インターネット接続とMCPクライアントが必要。利用はレート制限対象で、専用Knowledge endpointの数値上限は公開ページに記載されていない。 |
| 統合AWS MCP Server | 別エンドポイントの統合サービス。未認証では読み取り専用のKnowledge系ツールのみ。公式の既定値は未認証で送信元IP・リージョンあたり5 req/s、認証済みでAWSアカウント・リージョンあたり10 req/s。超過時は429。これらの数値を上記のKnowledge endpointへ当てはめない。 |

このCodexセッションにはAWS Knowledge MCPの直接接続がなく、今回はブラウザ検索で公式情報を確認した。将来のスキル実行で使うには、MCPクライアントに上記HTTP endpointを登録する。読み取り専用ナレッジ利用にAWSアカウントは不要。
